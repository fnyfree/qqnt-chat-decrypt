# nt_msg.db 消息表结构（QQ NT）

解密后是标准 SQLite。核心表：

| 表 | 内容 |
|---|---|
| c2c_msg_table | 私聊消息 |
| group_msg_table | 群聊消息 |
| c2c_msg_flow_table / group_msg_flow_table | 消息流索引 |

## c2c_msg_table 关键列

| 列 | 含义 |
|---|---|
| 40001 | 自增主键 |
| 40011 | 消息状态（0/1 常见于无效/撤回） |
| 40020 | 发送者 uid（u_ 开头） |
| 40021 | 对方 uid |
| 40027 | 会话标识（索引前缀） |
| 40050 | 时间戳，**unix 秒**（不是毫秒） |
| 40800 | 消息体 protobuf BLOB |

群聊表另有 40030/40033（群号相关）。

## 40800 protobuf 结构

```
MsgBody {
  repeated MsgContent content = 40800;   # 一条消息可有多段（图文混排）
}
MsgContent {
  45001 = 段ID
  45002 = 内容类型（2=表情 3/8=图片 4=语音 6=文件；文本段见45101）
  45101 = 文本正文（UTF-8）
  ...   = 各类型特有字段（文件名/URL等，多为可打印串）
}
```

解析要点：
- 顶层只遍历 field 40800（wire type 2），每段独立解析
- 段顺序即显示顺序，不要合并
- 非文本段没有 45101 时，按 45002 打 `[图片]`/`[文件]` 标注；段内其他可打印字段可补充细节（如文件名）

## 定位会话

- 已知对方昵称/关键词：`WHERE [40800] LIKE '%关键词%'` 反查 40020/40021
- 我的 uid：QQ 主界面自己的 uid，或 `md5(md5(uid)+"nt_kernel")` 对比 nt_db 目录名 `nt_qq_<hash>` 验证
